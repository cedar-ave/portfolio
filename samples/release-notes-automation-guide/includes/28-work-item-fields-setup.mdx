# Custom fields on Azure DevOps work items

[Logic](../27-work-item-logic) behind how certain fields are marked on certain work items determines if contents in a work item form a release note, known issue, critical and high bug, or none.

A custom **RN** tab on Releases, Product Backlog Items, and Bug work items contains [custom fields](../29-fill-out-work-items). They custom fields were set up with the following steps:

#### Add or change fields

- Go to the Vertex process in Azure DevOps.
- Go to the bug or feature template.
- Click the **RN** tab.

##### Change a dropdown field

- Click the dropdown field.
- Click **Edit field**.
- Add the list item to the dropdown.

On bugs, the **Version(s) Affected** field is on both the **Details** and **RN** tabs. You only need to update one of them. The same field manifests in both places.

#### Get a list of Azure DevOps work item fields in the Vertex process

```plaintext
https://dev.azure.com/<org>/Vertex/_apis/wit/fields?api-version=5.1
```

In cURL:

```curl
curl -u EMAIL:ADO_PAT --request GET "https://dev.azure.com/<org>/Vertex/_apis/wit/wiql/<query-id>?api-version=5.1"
```

In an application like Postman:

Basic authorization uses:
- Send a `GET` request to `https://dev.azure.com/<org>/Vertex/_apis/wit/fields?api-version=5.1`
- Username: `EMAIL`
- Password: `ADO_PAT`
