# Structured authoring in Paligo

:::important

Proprietary content is genericized. Paligo's internal attributes are removed in XML code blocks for readability.

:::

The following sample comes from a Paligo library of ~750 topics and reusable components behind ~20 guides. Six levels of structured reuse were in place:

- Topics placed in more than one spot
- Topics inside other topics
- Reusable step sets
- Reusable notes
- Shared sentences and paragraphs
- Variables like product names, users, and icons

Following is a sample of one topic published in two guides. The topic in one guide is customized for one audience and the topic in the other guide is customized for another based on `audience` attributes.

## The shared topic

```xml title="Initiate a report review"
<section>
  <title>Initiate a report review</title>
  <!-- Reusable note: Link names customized note (both audiences) -->
  <xi:include parse="xml" href="UUID-296d2e52-ffab-0ea5-524f-cf3513a5f2a1"/>
  <!-- Each <phrase> in this topic is the product name variable: "Clearpath" -->
  <important audience="Employee Compliance">
    <para>
      This information is for organizations handling compliance internally, not for
      organizations working with <phrase xinfo:variable="19" xinfo:varset="320"/>'s managed compliance team.
    </para>
  </important>
  <para>
    <phrase xinfo:variable="19" xinfo:varset="320"/> supports customized workflows for sharing a compliance report
    with reviewers and tracking its progress. Customized workflows are designed through
    collaboration between <phrase xinfo:variable="19" xinfo:varset="320"/> and your organization to meet your
    organization's policies and procedures.
  </para>
  <para>
    Reports typically fall into one of two categories: <emphasis>complete</emphasis> (no
    flags are raised) or <emphasis>complete with concerns</emphasis> (flags are raised).
  </para>
  <para audience="Employee Compliance">
    A common report approval process is that an organization sends a complete report to a
    compliance manager, who reviews and approves the report. However, if the report is
    complete with concerns, it is sent to the compliance manager and compliance committee
    for review and approval.
  </para>
  <!-- Included topic: Steps to initiate a report review -->
  <xi:include parse="xml" href="UUID-8c12467e-80cf-de83-a66a-bf33fc2ea948"/>
</section>
```

## The reusable pieces it pulls in

```xml title="Steps to initiate a report review (included topic)"
<section>
  <title>Steps to initiate a report review</title>
  <procedure>

    <xi:include parse="xml" href="UUID-4f2b8e61-3c7a-4d95-b0e2-7a1c5d9e3f84"/>
    <!-- Reusable steps: Employee's page navigation (Employee Compliance only) -->
    <xi:include parse="xml" href="UUID-c70510c8-2a61-489e-4328-584e32021cc3"/>
    <!-- Reusable steps: Review cycle navigation (Site Compliance only) -->
    <xi:include parse="xml" href="UUID-079361d6-03ec-e6de-e310-059d58daa63d"/>
    <step>
      <para>
        On the <emphasis role="bold">Details</emphasis> tab in the modal at right, go to
        the <emphasis role="bold">Summary</emphasis> section and click
        <phrase xinfo:variable="133" xinfo:varset="320"/> next to <emphasis role="bold">Status</emphasis>.
        <!-- "the pencil icon" + pencil image variable -->
      </para>
    </step>
    <step>
      <para>
        In the <emphasis role="bold">Status</emphasis> field dropdown, select the next
        status in the compliance approval workflow. This likely is customized for your
        organization. If you're using default functionality, the next status is
        <emphasis role="bold">Complete</emphasis>.
      </para>
    </step>
    <step>
      <para>
        In the <emphasis role="bold">Type</emphasis> field dropdown, select
        <emphasis role="bold">Initial</emphasis> if this is the first compliance review.
        Select <emphasis role="bold">Renewal</emphasis> if it's not the first time.
      </para>
    </step>
    <step>
      <para>Click <emphasis role="bold">Save</emphasis> at the bottom of the screen.</para>
    </step>
  </procedure>
</section>
```
