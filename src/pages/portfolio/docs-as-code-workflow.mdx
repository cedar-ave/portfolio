# Docs-as-code workflow

I set up a docs-as-code workflow from scratch for an organization's help content ecosystem. I managed content as Markdown in a Git repo, built the site using the DocFX static-site generator, and deployed to production with an automated pipeline. 

## Content development workflow

<HelpSiteWorkflow />

### Linting

The workflow used the Vale linting tool to check style, grammar, and spelling. Vale checked content against [a custom house style of 96 rules](https://github.com/cedar-ave/sample-linting/tree/main/vale-rules), including rules drawn from Microsoft, GitLab, and other public style guides. The markdownlint tool, with a config tuned for DocFX, checked Markdown formatting. For what neither tool could catch, such as broken links, images without alt text, and page titles that didn't match their headings, I wrote [custom scripts](https://github.com/cedar-ave/sample-linting/tree/main/linting-scripts).

### Contributions

Article pages included an **Edit this page** link, which let contributors submit changes as pull requests. A **Contributor reference** link went to the [Docs-as-Code Contributor Guide](/samples/contributor-guide/02-prerequisites), which walked contributors through the steps.
