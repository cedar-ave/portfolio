# AI chatbot

I contributed to Zendesk AI Agent chatbot development at an organization that wanted to supplement its online help center with AI messaging features.

Because the AI chatbot is proprietary, following is an overview of the project with details anonymized.

## The problems

**Customer organizations were on multiple versions of multiple platforms.** A help article titled **How to achieve Task A** for Platform X was different from a help article titled **How to achieve Task A** for Platform Y. A generative answer from the AI chatbot needed to be scoped to a certain subset of answers based on characteristics of the user's organization, which was not functionality offered out of the box.

**The AI chatbot did not capture a user's information when they entered a prompt.** This was true even if the user was logged into the Zendesk help site before accessing the AI chatbot. That meant we needed alternative means to retrieve that data ourselves if we were to customize answers based on their organization's platform. Consultants suggested we achieve this by asking the user to enter their email address each time they initiated the chatbot, but this would have created too much friction.

**A conversation escalated to the support team as a ticket would not include any user data.** This meant the support agent would need to have manual back-and-forths with the user to collect foundational information. Ideally, all data about a user would be provided to support with the ticket without requiring the user to provide it.

## Sample

A *knowledge rule* scoped the AI chatbot to pull content only from articles that matched the platform of a user's organization.

```txt
1. Welcome the user.
2. Invite the user to ask a question.
3. Get information about the user through the SunCo [Zendesk API chatbot] API and put them in the specified parameters.
3.1. Get the user's email address and set the parameter {{emailAddress}}.
3.2. Get the user's name and set the parameter {{userName}}
3.3. Get the user's organization and set the parameter {{organizationName}}.
3.4. Get the organization's platform and set the parameter {{organizationPlatform}}
4. Provide a generative AI response.
4.1. If the user is in Segment A, apply Knowledge Search Rule A for all questions, including all follow-up questions, asked by the user during the conversation.
4.2. If the user is in Segment B, apply Knowledge Search Rule B for all questions, including all follow-up questions, asked by the user during the conversation.
4.3. If the user is in Segment C, apply Knowledge Search Rule C for all questions, including all follow-up questions, asked by the user during the conversation.
4.4. If the user uses the terms "abc", "def", "ghi", "jkl", or similar terms in combination with "mno", "pqr", "stu", "vwx", "yza", or "bcd", prioritize responses from knowledge articles with the labels "efg" or "hij."
5. If the user's question is not answered, create a ticket.
5.1. Run Action D to map the parameters defined in step 3.1, 3.2, and 3.3 to ticket fields. The action already maps these parameters to existing ticket fields.
```
