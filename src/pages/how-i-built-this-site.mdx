# How I built this site

Most of my professional work is under non-disclosure agreements, so this site is my portfolio.  Following are details about how I built, deployed, and run it with automated pipelines and AI tools.

## Site infrastructure

This site is managed with a docs-as-code methodology:

- Content stored as Markdown files (MDX) in Git
- Static-site generator builds the site
- GitHub actions run automated tests and build the site
- Netlify hosts

### Static-site generator

The site is built with [Docusaurus](https://docusaurus.io/), a popular static-site generator for documentation websites used by companies like React Native, Electron, and Algolia DocSearch. Desirable Docusaurus features include:

- **MDX file support**: Docusaurus supports MXD files instead of just regular Markdown, which lets me embed React components like the interactive samples I share on my [Portfolio](/portfolio/) pages.
- **Plugin support**: Docusaurus supports plugins to easily implement features like Google Analytics tracking, search functionality, a blog, documentation layouts, diagrams, and AI optimization.
- **Customization**: I can easily swizzle any theme component to customize it, which lets me customize portfolio sample pages.
- **Credibility and maintenance**: Meta maintains it.

## AI agent optimization

### Agent discoverability and consumption

This site follows the [Agent-Friendly Documentation Spec](https://agentdocsspec.com), which provides tested and proven standards for serving a documentation site that agents can find and process. Examples include:

- Serving an `llms.txt` file under 50K characters, formatted according to the [llmstxt.org](https://llmstxt.org) standardization proposal
- Serving `.md` URLs for each article
- Pointing agents to the `llms.txt` file via the HTML DOM and served `.md` files
- Enabling `Accept: text/markdown` content negotiation for AI agents that prefer Markdown over HTML, via a Netlify function
- Served Markdown files deliver all content with one fetch
- Proper code fences and error codes
- Content matches between HTML and served Markdown files
- Many more

This site also passes the [AFDocs](https://afdocs.dev) companion test on how well agents can consume this site.

### Linting

The pipeline fails if issues are detected with any of the following:

- Style deviations (Vale)
