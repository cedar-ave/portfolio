# The API reference page

The **Norway Data API** navbar link opens `/api-reference`, an interactive API reference rendered by [Scalar](https://scalar.com/products/api-references/integrations/docusaurus). The API itself, its OpenAPI spec, its contract test, and its docs live in their own repo, [cedar-ave/norway-data-api](https://github.com/cedar-ave/norway-data-api), which deploys to its own Netlify site. This page covers only how this site connects to it.

<QuickReference>

- `@scalar/docusaurus` adds the `/api-reference` route and renders the spec. Its script version is pinned in `docusaurus.config.js`.
- This site's `netlify.toml` proxies `/api/norway-data/*` and `/openapi/norway-data.yaml` to `norway-data-api.netlify.app`, so the API and its spec are served from `www.marlasowards.com`.
- `npm start` doesn't apply Netlify proxy rules, so in development the page loads the spec straight from the API's site.
- To change the API, its data, or the reference page's text, work in the [norway-data-api repo](https://github.com/cedar-ave/norway-data-api). The reference page picks up the change as soon as that site deploys, with no rebuild here.

</QuickReference>

## How a request flows

```text
Browser on www.marlasowards.com/api-reference   (this repo)
   │  loads the spec   → /openapi/norway-data.yaml
   │  Test Request     → /api/norway-data/v1/...
   ▼
www.marlasowards.com: proxy rules in netlify.toml   (this repo)
   ▼
norway-data-api.netlify.app                      (norway-data-api repo)
   ├── public/openapi/norway-data.yaml
   └── Netlify Function: netlify/functions/norway-data/
```

## The proxy rules

```toml title="netlify.toml"
[[redirects]]
  from = "/api/norway-data/*"
  to = "https://norway-data-api.netlify.app/api/norway-data/:splat"
  status = 200

[[redirects]]
  from = "/openapi/norway-data.yaml"
  to = "https://norway-data-api.netlify.app/openapi/norway-data.yaml"
  status = 200
```

A redirect with `status = 200` is a rewrite. The visitor's browser only ever talks to `www.marlasowards.com`, so:

- The API's public URLs and published code samples use this site's domain, not `netlify.app`.
- The reference page and the API share an origin, so **Test Request** calls never run into CORS restrictions.

The rules apply to deploy previews too.

## The plugin

```js title="docusaurus.config.js"
[
  '@scalar/docusaurus',
  {
    route: '/api-reference',
    showNavLink: false,
    // Pinned so a Scalar release can't change the page unannounced.
    cdn: 'https://cdn.jsdelivr.net/npm/@scalar/api-reference@1.73.1',
    configuration: {
      url:
        process.env.NODE_ENV === 'development'
          ? 'https://norway-data-api.netlify.app/openapi/norway-data.yaml'
          : '/openapi/norway-data.yaml',
    },
  },
],
```

- **`route`** is the page's URL.
- **`showNavLink: false`** stops the plugin from adding its own navbar link, which it always puts at the end of the left side. The link is added by hand in `themeConfig.navbar.items` instead, before Blog. See [Navbar](../site-config/navbar).
- **`cdn`** pins Scalar's script version. By default the plugin loads the latest version, which could change the page with no change in this repo.
- **`configuration.url`** is where the page loads the spec from. In production it's the proxied path. In development it's the API's own site, because `npm start` doesn't apply the proxy rules. The API's site allows cross-origin requests for `/openapi/*` so this works.

:::note

The plugin adds Scalar's `<script>` tag to every page on the site, not only `/api-reference`. That's how the plugin is built. If page weight on other pages ever matters, replace the plugin with a custom page that loads Scalar only on its own route.

:::

The plugin hides Scalar's dark mode toggle, and the page follows the site's light or dark mode.

## Local development

With `npm start`, the reference page loads the spec from the live API site, and the page's code samples and **Test Request** calls go to the production API at `www.marlasowards.com` (the server URL in the spec). Nothing needs to run locally.

To work on the API itself, clone the [norway-data-api repo](https://github.com/cedar-ave/norway-data-api) and see its README.

## Upgrade Scalar

Change the version in the `cdn` URL, then check the reference page: the sidebar sections, the **Test Request** button, and the code samples. The spec's introduction mentions the **Test Request** label by name, so if a new version renames it, update the spec in the API repo.

## Troubleshooting

### The reference page is empty

The page couldn't load the spec. Check each step of the path:

1. `curl -I https://norway-data-api.netlify.app/openapi/norway-data.yaml` should return `200`. If it doesn't, the API site's latest deploy failed.
2. `curl -I https://www.marlasowards.com/openapi/norway-data.yaml` should also return `200`. If step 1 works but this doesn't, check the proxy rules in `netlify.toml`.

### Test Request shows "Failed to fetch"

The request didn't reach the function. Run the same checks with `/api/norway-data/v1/facts/10` in place of the spec path. For problems inside the API, see the troubleshooting section of the [API repo's maintenance docs](https://github.com/cedar-ave/norway-data-api/blob/main/docs/maintenance.md).
