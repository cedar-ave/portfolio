# The docs area

How this documentation site (the thing you're reading) is itself organized — the sidebar, categories, and page ordering.

<QuickReference>

- The sidebar is **auto-generated from the `docs/` folder structure** — see [sidebars.js](../../sidebars.js). There's no hand-written sidebar list to maintain.
- Each top-level folder under `docs/` is a sidebar category, configured by a `_category_.json` file inside it (`label`, `position`, optional `link`).
- Each page's order within its category comes from `sidebar_position` in its own frontmatter.
- [overview.mdx](../overview.mdx) is a separate, hand-maintained table mapping each site customization to its file and doc page — update it when adding a new customization doc.

</QuickReference>

## Sidebar: generated, not hand-written

[sidebars.js](../../sidebars.js) defines a single sidebar (`tutorialSidebar`) with:

```js title="sidebars.js"
tutorialSidebar: [{type: 'autogenerated', dirName: '.'}],
```

`dirName: '.'` means the whole sidebar mirrors the `docs/` directory tree starting at its root. Adding a new `.mdx` file or folder under `docs/` is enough to add it to the sidebar — nothing in `sidebars.js` needs to change.

## Categories: one folder, one `_category_.json`

Every subfolder of `docs/` that should render as a collapsible sidebar category has a `_category_.json`:

```json title="docs/styling/_category_.json"
{
  "label": "Styling",
  "position": 4,
  "link": {
    "type": "generated-index",
    "description": "The site's color palette and where it's applied."
  }
}
```

- `label` — the text shown in the sidebar for that category.
- `position` — sort order relative to sibling categories/pages. Current top-level positions leave gaps (4, 5, 10, 11, 12, 13, 14) so new categories can be slotted in later without renumbering everything.
- `link.type: "generated-index"` — gives the category a clickable landing page that auto-lists its child pages, with an optional `description` shown above the list. Categories without a `link` (e.g. `blog`, `build-deploy`, `home-page`, `site-config`) aren't clickable themselves — only their children are.

Current categories and positions:

| Folder | Label | Position |
| --- | --- | --- |
| `docs/` (this category) | Docs | 2 |
| `styling/` | Styling | 4 |
| `troubleshooting/` | Troubleshooting | 5 |
| `visuals/` | Visuals | 10 |
| `home-page/` | Home page | 11 |
| `build-deploy/` | Build & deploy | 12 |
| `blog/` | Blog | 13 |
| `site-config/` | Site config | 14 |

`overview.mdx` lives at the `docs/` root (no category) at position 1, so it sorts above every category, including this one.

## Pages: order via frontmatter

Within a category, each `.mdx` file sets its own order with `sidebar_position` frontmatter:

```mdx title="docs/styling/colors.mdx"
---
sidebar_position: 1
---
```

That's also the pattern most pages here follow for a scannable top section:

```mdx
import QuickReference from '@site/src/components/QuickReference';

# Page title

<QuickReference>

- Bullet-point summary of the key facts, for someone skimming.

</QuickReference>

## Deeper sections

Prose and code samples with more detail below.
```

## The `overview.mdx` index

[overview.mdx](../overview.mdx) is not generated — it's a hand-maintained table of every customization made to the stock Docusaurus install, each row linking to the page that documents it:

```mdx title="docs/overview.mdx"
| Customization | Where to change it | Details |
| --- | --- | --- |
| Gallery component | `src/components/Gallery` | [Gallery](visuals/gallery) |
```

When adding a new doc page for a new customization, add a row here too — it's the one place meant to give a full, flat view of everything, since the sidebar itself only shows structure, not a description of what each page covers.

## Doc plugin config

A couple of docs-wide behaviors are set in `docusaurus.config.js` rather than per-page:

```js title="docusaurus.config.js"
docs: {
  sidebarPath: './sidebars.js',
  remarkPlugins: [remarkImageSize],
  editUrl: 'https://github.com/...',
},
```

- `sidebarPath` points at the `sidebars.js` described above.
- `remarkPlugins` adds markdown-processing plugins (e.g. `remarkImageSize`) that apply to every doc page.
- `editUrl` controls the "Edit this page" link; see [Build flags and edit links](../build-deploy/build-flags-and-edit-links) for details.

## Adding a new doc page

1. Decide whether it belongs in an existing category folder or needs a new one.
2. If it's a new category, add the folder and a `_category_.json` with a `label` and a `position` (leave gaps, matching the existing spacing).
3. Create the `.mdx` file with a `sidebar_position` in frontmatter, following the `QuickReference` + sections pattern above.
4. Add a row to [overview.mdx](../overview.mdx) linking to the new page.
