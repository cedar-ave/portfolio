# How I built a REST API so I could build and orchestrate API docs

Claude and I built a REST API. I've built developer portals, edited content in OpenAPI and Swagger YAML files, submitted bugs when samples don't work, and used a lot of REST API documentation, but I've never had the chance to fully document one, create working samples, or set up a pipeline for self-healing API documentation. Here's how I used Claude to build the public Norway Data API (because who doesn't need a programmatic way to get more facts about Norway?).

{/* truncate */}

## The strategy

Claude helped me define and execute a strategy. I used a prompt like this:

```txt
I want a small, public, read-only REST API as a portfolio sample for API documentation. Visitors must be able to run the code samples against a live server. My site is Docusaurus on Netlify. Propose an architecture before building anything.
```

I asked Claude to review the architecture from three perspectives and get their criticisms and recommendations:

- Principal API engineer
- Principal API tech writer
- Principal SecOps engineer

Claude provided detailed reports from each perspective, which helped me understand what . That helped me settle on a simple architecture:

- **Live backend**: A [Netlify Function](https://docs.netlify.com/build/functions/overview) serves a small, fixed dataset.
- **Spec**: An [OpenAPI 3.1](https://spec.openapis.org/oas/v3.1.0.html) file describes the endpoints.
- **API docs on my site**: [Scalar](https://scalar.com) (an open-source, interactive API documentation platform) renders the spec.

## The guts

Based on Claude's technical recommendations, I prompted Claude to build the API with something like:

```txt
Create a Netlify Function that serves a fixed dataset of facts about Norway from a JS module. No database. Version it under /norway-data/v1, with list and detail endpoints, pagination, and RFC 9457 errors.
```

The Netlify Function contains the data about Norway and routes requests, paginates them, and sends responses.
