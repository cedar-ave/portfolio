# How I made my site easier for AI agents to find and read with the Agent-Friendly Documentation Spec

"Can agents read your documentation?" This is the question Dachary Carey asks those of us who build and manage docs sites. Dachary's [Agent-Friendly Documentation Spec](https://agentdocsspec.com) defines 28 standards docs sites need to meet to serve AI agents well. I put the spec up against my own site by running it through Dachary's companion [AFDocs](https://afdocs.dev) tool, which gave me a scorecard on where my site stands and what I should fix. Here's what I learned from Dachary's crystal-clear spec and why I think every docs site owner should run AFDocs as part of a CI pipeline.

## The spec

First, a look at the spec. Dachary's testing and research pointed to factors in several categories that determine if a site is optimized for agents, but to get a taste of the spec, here are some examples from the content discoverability category.

### Serve an `llms.txt` file

An `llms.txt` file is a Markdown file stored at or near the root of a site that acts like a table of contents agents use to find the most meaningful information. That means agents don't have to parse through JavaScript, layout markup, and content that isn't relevant, so responses are faster and better quality.

According to the spec, the file should exist in certain path patterns. For example:

```
docs.example.com/llms.txt
example.com/docs/llms.txt
Etc.
```

### Format the `llms.txt` file properly

The `llms.txt` file should follow the structure defined in the [llmstxt.org proposal](https://llmstxt.org). For example:

```markdown
# Title

> Description goes here

Details go here

## Section name

- [Link title](https://link_url): Link details

## Optional

- [Link title](https://link_url)
```

### Limit the size of the `llms.txt` file

If the `llms.txt` file is too long, agents won't read it all. Keep it under 50K characters to avoid agent truncation limits.

### Serve Markdown versions of each page

Agents like Claude Code, Cursor, and OpenCode ask websites for Markdown first when they fetch a page. Serve articles as Markdown files (with `.md` URL endings) alongside the HTML files. For example:

```
docs.example.com/add-a-file.html
docs.example.com/add-a-file.md
```

### Keep Markdown pages under 50K characters

Agent truncation limits can mean long Markdown pages aren't fully read in a single agent fetch. Break down large pages into smaller ones so that no single page is more than 50K characters.

### Point agents to the `llms.txt` file

Agents need to be told to look for an `llms.txt` file in the first place. Add directives for agents in the code of the HTML and Markdown files. The spec recommended something like:

```
For AI agents: a documentation index is available at /llms.txt
```

## The test

I ran the [AFDocs](https://afdocs.dev) test to get a scorecard on how well my site matched up to the spec. AFDocs couldn't be easier to set up and couldn't run more smoothly. If you have Node.js 22, no install is necessary. Just run:

```
npx afdocs check https://docs.example.com --format scorecard
```

The first time I ran it I got this warning in the content discoverability category:

```
  ⚠ llms-txt-directive-html: llms.txt directive found in HTML of 1 of 50 sampled pages (49 missing)
      Learn more: https://agentdocsspec.com/spec/web/content-discoverability/#llms-txt-directive-html
```

This is a problem for AI agents that ask for HTML instead of Markdown (like OpenAPI Codex and GitHub Copilot). Thanks to the test results, I knew I needed to add a directive in `<head>` in each HTML page.

My site had other deficiencies in other categories, which took time to work out. But after a lot of work, I was so proud to get this scorecard. Still working toward all As!

```
  Overall Score: 98 / 100 (A)

  Category Scores:
    Content Discoverability              100 / 100 (A+)
    Markdown Availability                 96 / 100 (A)
    Page Size and Truncation Risk         94 / 100 (A)
    Content Structure                    100 / 100 (A+)
    URL Stability and Redirects          100 / 100 (A+)
    Observability and Content Health      99 / 100 (A)
    Authentication and Access            100 / 100 (A+)
```

## The CI pipeline check

Finally, I [added AFDocs checks in my CI pipeline](https://afdocs.dev/ci-integration) alongside [Vale](https://vale.sh), [lychee](https://lychee.cli.rs), and [codespell](https://github.com/codespell-project/codespell). If any single check comes back as a failure, the job fails. I need to know if agents will have issues finding and reading my content, and this lets me know.
