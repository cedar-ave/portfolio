This help site was built in Zendesk.

## Problem statement

Two software applications had some parity but not completely. For example, two **How to audit rosters** articles existed - one for the first software app and one for the second - but they contained different steps.

Default Zendesk help site theme didn't account for this.

## Information architecture
The first rung of the information architecture was clear entry points into content specific to the app the user is using.

I customized the theme code to add features not supported by the default theme, including search filtering capabilities, a navbar dropdown with custom contents, content tags displayed on articles, heading anchors, and more.
